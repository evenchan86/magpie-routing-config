# 路由模式库

7 个可复用模式。每个模式说明意图、结构、字段写法与取舍。模板 `templates/groups.template.json` 是这些模式的组合实例。

## 1. 意图分层路由

**意图**：按任务类型选模型，难题用强模型、琐事用便宜模型。
**结构**：组配 `classifier` + 一组 `intent` 规则 + 兜底。

内置 7 条互斥意图（默认推荐，可增删）：

| 意图 | 路由角色 |
|---|---|
| 写测试或修失败的测试 | code/general |
| 简单问答、查文档或命令 | fast/cheap |
| 实现新功能或修局部 bug | code/general |
| 重构、迁移或跨文件大改动 | reasoning/strong |
| 架构设计、方案选型或疑难排查 | reasoning/strong |
| 前端界面、样式或视觉还原（含截图） | design/ui |
| 审查代码或 review 改动 | code/general（可升 reasoning/strong） |

**互斥划界**：「实现新功能」强调功能逻辑，「前端界面」强调视觉/样式；修失败测试归测试，修产品代码归实现。
**取舍**：分类器有延迟（观测中位数约亚秒级，尾部可达数十秒）且可能判「都不是」——意图别写太细，保持互斥；分类器模型必须便宜。

## 2. 推理触发升级

**意图**：需要深思的请求自动升级到强模型，与意图分类无关。
**写法**：`{"use": "<role:reasoning/strong>", "effort": "on"}`，放在意图规则之后、兜底之前。
**取舍**：简单请求不会触发；与意图规则叠加时注意顺序（首条命中）。

## 3. 成本分级兜底

**意图**：分类器判「都不是」时也有确定的便宜出口。
**写法**：`{"use": "<role:fast/cheap>", "compact": true}` 作为组内最后一条。
**取舍**：兜底模型不宜太弱，它承接所有未分类流量（观测中占比不低）。

## 4. 故障转移链

**意图**：目标模型失败（限流/超时）时自动降级。
**写法**：`"more": ["<role:code/general>", "<role:fast/cheap>"]`，按序尝试。
**取舍**：链越长尾延迟越高；转移目标应与原模型能力同档或相邻，避免质量骤降。

## 5. 长上下文摘要组

**意图**：会话压缩/摘要只要长上下文、快、便宜，与编码质量无关。
**结构**：独立 compact 组（members 为 context/long + fast/cheap），**不经意图分类器**。
**取舍**：摘要走独立组而非 coder 组规则，避免摘要流量抢占强模型。

## 6. UI 设计专用路由

**意图**：界面、样式、截图还原走多模态模型。
**写法**：`{"use": "<role:design/ui>", "more": ["<role:code/general>"], "intent": "前端界面、样式或视觉还原（含截图）"}`。
**取舍**：多模态能力以实测为准（模型目录的模态标注可能是统一填充的元数据）；纯企业官网类任务 code/general 往往已够。

## 7. 会话粘性（affinity）

**意图**：同会话沿用同一模型以利用 prompt cache，省钱省延迟。
**状态**：运行机制已观测到（会话内跨轮粘住同一规则/模型），但**配置入口未定位**，暂无可交付模板。见 schema.md 待验证清单。
**建议**：实测你的 magpie 版本后再启用；不要凭日志字段反推配置写法。
